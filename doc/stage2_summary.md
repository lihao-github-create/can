# 第二阶段总结：理解一条 CAN 报文

本阶段学习了原始字节与信号值的区别，以及字节序、有无符号、位提取和物理值换算。下面的信号定义均为教学假设，不是实车报文的真实定义。

返回：[学习指南](../learn_guide.md) · 上一阶段：[读取和观察 BLF](stage1_summary.md)

## 1. 报文标识、原始数据与信号含义

第一阶段实际读取过：

```text
通道=1  ID=0x0B4  长度=8字节
数据=06 07 00 5f 00 00 ff ff
```

| 层次 | 示例 | 能回答什么 |
|---|---|---|
| 报文标识 | 通道 1、标准帧 ID `0x0B4` | 正在观察哪一类消息 |
| 原始数据 | `06 07 00 5f 00 00 ff ff` | 收到了哪些字节 |
| 信号含义 | 需要对应的定义 | 哪些位代表什么，以及如何换算 |

CAN ID 不是车速值，一个字节也不一定就是一个信号。一条报文可以包含多个信号，一个信号可以占几个 bit，也可以跨越多个字节。

## 2. Byte、bit 和进制

一个 Byte（字节）包含 8 个 bit（位），每个 bit 只能是 0 或 1。一个十六进制数字对应 4 个 bit，因此两个十六进制数字可以表示一个字节。

| 十六进制 | 十进制 | 8 位二进制 |
|---|---:|---|
| `06` | 6 | `00000110` |
| `07` | 7 | `00000111` |
| `5F` | 95 | `01011111` |
| `FF` | 255 | `11111111` |

这些只是同一个无符号数值的不同写法。把 `5F` 转成 95，并不代表车速就是 95 km/h。

本章单字节示例约定最低位为 bit 0：

```text
位编号：7 6 5 4 3 2 1 0
0x06： 0 0 0 0 0 1 1 0
```

因此 `0x06` 的 bit 1 和 bit 2 为 1。具体含义仍需信号定义。

可以在项目根目录运行以下命令，复习三种表示方式：

```bash
python3 - <<'PY'
data = bytes.fromhex("06 07 00 5f 00 00 ff ff")
for index, value in enumerate(data):
    print(
        f"Byte {index}: 十六进制={value:02X}  "
        f"十进制={value:3d}  二进制={value:08b}"
    )
PY
```

## 3. 字节序：如何组合多个字节

假设 `10 27` 两个完整字节共同表示一个 16 位无符号整数：

| 字节序 | 规则 | 组合结果 | 十进制 |
|---|---|---|---:|
| 小端 Little Endian | 前面的字节是低位字节 | `0x2710` | 10000 |
| 大端 Big Endian | 前面的字节是高位字节 | `0x1027` | 4135 |

```text
两个字节组成的无符号整数 = 高位字节 × 256 + 低位字节

小端：0x27 × 256 + 0x10 = 39 × 256 + 16 = 10000
大端：0x10 × 256 + 0x27 = 16 × 256 + 39 = 4135
```

高一个字节相当于左移 8 位，权重是 `2⁸ = 256`，不是乘以 8。字节序改变的是解释规则，原始字节并没有改变。

练习结果：

| 原始字节 | 按小端解释 | 按大端解释 |
|---|---:|---:|
| `01 00` | 1 | 256 |
| `02 00` | 2 | 512 |

Python 可以直接组合完整字节：

```python
data = bytes.fromhex("10 27")
print(int.from_bytes(data, byteorder="little", signed=False))  # 10000
print(int.from_bytes(data, byteorder="big", signed=False))     # 4135
```

`signed=False` 表示按无符号整数解释。这里的例子都是完整字节组成的整数；实际 DBC 中跨字节、非字节对齐的信号还需要遵循对应的起始位和位编号规则。

## 4. 原始值与物理值

提取并解释得到的整数叫原始值（raw），还需要按定义换算：

```text
物理值 = raw × factor + offset
```

- `factor`：系数，决定原始值每增加 1 对应多大的物理变化。
- `offset`：偏移，在乘以系数后加上。
- 单位也由信号定义确定，不能从原始字节猜测。

例如，假设车速占 Byte 0～1，为小端无符号整数，系数为 0.01、偏移为 0、单位为 km/h，则 `10 27` 表示：

```text
raw = 10000
车速 = 10000 × 0.01 + 0 = 100 km/h
```

温度练习的定义是：16 位无符号、小端、factor = 0.1、offset = -40、单位为 °C。

| 原始字节 | raw | 换算过程 | 温度 |
|---|---:|---|---:|
| `02 01` | `0x0102 = 258` | `258 × 0.1 - 40` | -14.2 °C |
| `90 01` | `0x0190 = 400` | `400 × 0.1 - 40` | 0 °C |

原始值是无符号整数，换算后的物理值仍然可以为负数，例如上表中的 -14.2 °C 来自偏移量。

## 5. 有符号与无符号

同一个字节按不同类型解释，得到的原始值可能不同：

| 原始字节 | 8 位无符号整数 | 8 位有符号补码 |
|---|---:|---:|
| `7F` | 127 | 127 |
| `80` | 128 | -128 |
| `FE` | 254 | -2 |
| `FF` | 255 | -1 |

8 位无符号整数范围是 `0～255`，8 位有符号补码范围是 `-128～127`。

对于 8 位补码，先把字节视为无符号值 u：

```text
如果 u < 128：有符号值 = u
否则：       有符号值 = u - 256
```

减 256 的规则仅适用于 8 位补码。一般 n 位补码在最高位为 1 时，需要用无符号值减去 `2ⁿ`。

已完成练习：收到 `FE`，定义为 8 位有符号补码、factor = 0.5、offset = 0、单位为 °C：

```text
raw = 254 - 256 = -2
温度 = -2 × 0.5 + 0 = -1 °C
```

## 6. 一个字节中的多个信号

信号可以只占几个 bit。假设一个字节包含以下三个无符号字段：

| 信号 | 位置 | 长度 |
|---|---|---:|
| 开关状态 | bit 0 | 1 bit |
| 模式编号 | bit 1～3 | 3 bit |
| 计数值 | bit 4～7 | 4 bit |

收到 `0xB6` 时：

```text
位编号：7 6 5 4 3 2 1 0
二进制：1 0 1 1 0 1 1 0
分组：  1011 | 011 | 0
         ↓      ↓    ↓
       计数值  模式  开关
         11     3    0
```

每个字段从高位向低位读取，例如模式字段按 bit 3、2、1 读为 `011`。

Python 提取方式：

```python
value = 0xB6
switch = value & 0b1
mode = (value >> 1) & 0b111
counter = (value >> 4) & 0b1111
print(switch, mode, counter)  # 0 3 11
```

- `>>` 右移：将目标字段的最低位移到 bit 0。
- `&` 按位与：通过掩码只保留需要的位。例如 `0b111` 保留最低三位。

已完成练习：`0x25 = 00100101`，分组为 `0010 | 010 | 1`，所以开关状态为 1、模式编号为 2、计数值为 2。

## 7. 综合练习与参考答案

教学报文为：

```text
ID：0x123
Data：90 01 FE 25
```

| 信号 | 位置 | 类型与字节序 | factor | offset | 单位 |
|---|---|---|---:|---:|---|
| 温度 A | Byte 0～1 | 小端、16 位无符号 | 0.1 | -40 | °C |
| 温度 B | Byte 2 | 8 位有符号补码 | 0.5 | 0 | °C |
| 开关状态 | Byte 3 的 bit 0 | 无符号，0=关、1=开 | 1 | 0 | — |
| 模式编号 | Byte 3 的 bit 1～3 | 无符号 | 1 | 0 | — |

参考答案：

1. 温度 A：`0x0190 = 400`，`400 × 0.1 - 40 = 0 °C`。
2. 温度 B：`0xFE` 按 8 位补码为 -2，`-2 × 0.5 = -1 °C`。
3. 开关状态：`0x25` 的 bit 0 为 1，表示开。
4. 模式编号：`0x25` 的 bit 1～3 为 `010`，结果为 2。

## 8. 解析流程与下一阶段

```text
确认通道、CAN ID 和帧格式
    ↓
按信号位置、长度和字节序提取数据
    ↓
按有符号/无符号规则解释，得到 raw
    ↓
raw × factor + offset
    ↓
结合单位或枚举定义，得到信号含义
```

仅凭原始字节不能确定真实信号。第三阶段将学习 DBC 如何记录消息和信号定义，包括起始位、位长度、字节序、符号、系数、偏移及单位，并结合匹配实车网络与版本的 DBC 进行解析。
